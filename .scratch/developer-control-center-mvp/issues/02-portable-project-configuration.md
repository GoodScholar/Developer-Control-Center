# 02: 手动创建可移植的单服务项目配置

**What to build:** 用户可以通过结构化表单定义一个开发服务，预览并生成带模式版本、相对路径、平台覆盖和环境引用的 `.devcontrol.toml`；无效配置不会进入执行阶段，并得到可操作错误。

**Blocked by:** 01/建立可持久化的项目注册闭环

**Status:** ready-for-agent

- [ ] 用户可以为已注册开发项目添加一个长期运行的开发服务。
- [ ] 服务表单支持程序、参数、相对工作目录、非敏感环境值和外部 `.env` 引用。
- [ ] Shell 模式默认关闭，并且只能由用户显式开启。
- [ ] 用户可以定义共享默认值及 macOS、Windows 的局部覆盖，而无需维护两份完整配置。
- [ ] 保存前展示完整配置预览，确认后生成带 `schema_version = 1` 的项目配置。
- [ ] 绝对路径、越出项目根目录的路径、未知模式版本和无效平台覆盖被拒绝并显示可操作错误。
- [ ] 环境变量值不会出现在错误、普通日志或界面事件中。
- [ ] 配置解析与校验通过公开模块行为测试，不断言内部数据结构。
